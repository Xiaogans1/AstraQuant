# AstraQuant 产品路线图

本路线图描述交付顺序和阶段出口，不替代后续按任务拆解的实施计划。

## Phase 0：仓库与契约

目标：让多端开发从第一天就有稳定边界。

交付：

- 产品设计、开源采用矩阵和 Git 规范。
- Monorepo 目录与开发工具链。
- 领域事件、时间、标的、订单、成交、持仓和账户契约。
- 配置、数据目录和凭据边界。
- Windows CI、代码质量和秘密扫描。

出口：新设备能够克隆仓库、安装依赖、运行最小测试；仓库不包含任何私人数据。

## Phase 1：桌面与本地平台骨架

目标：建立可安装、可升级、可观测的桌面基础。

交付：

- Tauri + React 桌面端。
- Python 本地 API 和 Worker 生命周期。
- SQLite 迁移、任务模型和本地日志。
- `Astra Minimal`、`Astra Light` 与主题令牌。
- 工作区布局和本地设置。

出口：桌面端可启动本地服务、运行示例任务、展示状态并安全退出。

## Phase 2：AI 可用的数据闭环

目标：导入、验证、查询和版本化本地市场数据，同时建立离线训练与未来实时推理共享的数据语义。

交付：

- 批处理 Provider、流式 Provider 契约，以及一个 A 股、一个期货样例适配器。
- Parquet 分区、DuckDB 查询和数据目录。
- 交易日历、复权、连续合约视图与质量报告。
- `Tick`、`Bar`、`FeatureFrame` 基础契约和 `event_time / available_time` 时态语义。
- as-of 查询、防未来数据泄漏检查和可重建特征快照。
- 数据中心 UI。

出口：相同数据和特征快照可以在不同设备通过用户自行准备的数据重建；批处理和流式数据遵循相同领域语义；Git 中只包含小型脱敏夹具。

## Phase 3：AI 研究与回测闭环

目标：从版本化特征、模型训练到信号和可重复回测报告。

交付：

- 特征工程、标签、训练/验证切分和至少一个 AI 基线模型。
- `ModelArtifact`、模型注册、评估门槛、`SignalFrame` 和参数管理。
- 撮合、费用、滑点、组合与基准。
- 实验记录、模型比较、运行对比、解释和报告。
- 可选 Qlib Provider 原型。

出口：固定数据快照和模型版本可重现训练、预测与黄金回测；防泄漏测试和确定性回放通过。

## Phase 4：实时 AI Paper Trading 闭环

目标：在无真实资金风险下验证实时行情、在线特征、模型推理和交易流程。

交付：

- Paper Gateway、行情回放、实时行情流和在线特征。
- 模型加载、在线推理、信号发布、延迟与漂移监控。
- 订单状态机、OMS、账户和持仓。
- 基础风险规则、紧急停止和复盘。
- 断线、重复、乱序和重启测试。

出口：同一模型的离线/在线特征在相同截止时刻一致；连续模拟运行稳定，信号、订单、成交、持仓和资金可追溯并对账。

## Phase 5：国内实盘适配

目标：在显式安全门后接入真实市场。

交付：

- vn.py/CTP 适配器。
- A 股券商接口调研和至少一个仿真/开发适配边界。
- 凭据管理、环境检查和实盘确认。
- 启动对账、交易时段、夜盘、平今和保证金语义。
- AI 信号发布审批、模型版本锁定、推理降级和人工紧急停止。
- 小规模人工监护试运行流程。

出口：通过接口合约、故障测试、安全评审和用户手动启用；默认仍为 Paper。

## Phase 6：深化与扩展

候选方向：

- 更多 A 股券商实盘适配。
- 因子库、深度学习、强化学习和组合优化。
- 本地大语言模型研究助手、自然语言实验编排和智能复盘。
- 多模型集成、模型漂移、影子模式与自动再训练审批。
- 私有远程执行节点与多设备只读监控。
- 插件 SDK、主题包和原创角色助手。
- 性能数据证明必要后引入 Rust 热点模块。
