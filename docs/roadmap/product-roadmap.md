# AstraQuant 产品路线图

本路线图描述交付顺序和阶段出口，不替代后续按任务拆解的实施计划。

## Phase 0：仓库与契约

目标：让多端开发从第一天就有稳定边界。

交付：

- 产品设计、开源采用矩阵和 Git 规范。
- Monorepo 目录与开发工具链。
- 领域事件、时间、标的、订单、成交、持仓和账户契约。
- 配置、数据目录和凭据边界。
- Windows CI、代码质量和秘密扫描。

出口：新设备能够克隆仓库、安装依赖、运行最小测试；仓库不包含任何私人数据。

## Phase 1：桌面与本地平台骨架

目标：建立可安装、可升级、可观测的桌面基础。

交付：

- Tauri + React 桌面端。
- Python 本地 API 和 Worker 生命周期。
- SQLite 迁移、任务模型和本地日志。
- `Astra Minimal`、`Astra Light` 与主题令牌。
- 工作区布局和本地设置。

出口：桌面端可启动本地服务、运行示例任务、展示状态并安全退出。

## Phase 2：数据闭环

目标：导入、验证、查询和版本化本地市场数据。

交付：

- Provider 接口和一个 A 股、一个期货样例适配器。
- Parquet 分区、DuckDB 查询和数据目录。
- 交易日历、复权、连续合约视图与质量报告。
- 数据中心 UI。

出口：相同数据快照可以在不同设备通过用户自行准备的数据重建，Git 中只包含小型脱敏夹具。

## Phase 3：研究与回测闭环

目标：从信号到可重复回测报告。

交付：

- `SignalFrame`、策略接口和参数管理。
- 撮合、费用、滑点、组合与基准。
- 实验记录、运行对比和报告。
- 可选 Qlib Provider 原型。

出口：固定样例策略通过黄金回测和确定性回放。

## Phase 4：Paper Trading 闭环

目标：在无真实资金风险下验证实时流程。

交付：

- Paper Gateway、行情回放和实时任务。
- 订单状态机、OMS、账户和持仓。
- 基础风险规则、紧急停止和复盘。
- 断线、重复、乱序和重启测试。

出口：连续模拟运行稳定，订单、成交、持仓和资金可对账。

## Phase 5：国内实盘适配

目标：在显式安全门后接入真实市场。

交付：

- vn.py/CTP 适配器。
- 凭据管理、环境检查和实盘确认。
- 启动对账、交易时段、夜盘、平今和保证金语义。
- 小规模人工监护试运行流程。

出口：通过接口合约、故障测试、安全评审和用户手动启用；默认仍为 Paper。

## Phase 6：深化与扩展

候选方向：

- A 股券商实盘适配。
- 因子库、机器学习和组合优化。
- 私有远程执行节点与多设备只读监控。
- 插件 SDK、主题包和原创角色助手。
- 性能数据证明必要后引入 Rust 热点模块。
