# AstraQuant 产品路线图

本路线图描述交付顺序和阶段出口，不替代后续按任务拆解的实施计划。

## Phase 0：仓库与契约

目标：让多端开发从第一天就有稳定边界。

交付：

- 产品设计、开源采用矩阵和 Git 规范。
- Monorepo 目录与开发工具链。
- 领域事件、时间、标的、信号和 Paper 虚拟成交/持仓契约。
- 配置、数据目录和凭据边界。
- Windows CI、代码质量和秘密扫描。

出口：新设备能够克隆仓库、安装依赖、运行最小测试；仓库不包含任何私人数据。

## Phase 1：桌面与本地平台骨架

目标：建立可安装、可升级、可观测的桌面基础。

交付：

- Tauri + React 桌面端。
- Python 本地 API 和 Worker 生命周期。
- SQLite 迁移、任务模型和本地日志。
- `Astra Minimal`、`Astra Light` 与主题令牌。
- 工作区布局和本地设置。

出口：桌面端可启动本地服务、运行示例任务、展示状态并安全退出。

## Phase 2：AI 可用的数据闭环

状态：**已完成（2026-07-28）**

目标：导入、验证、查询和版本化本地市场数据，同时建立离线训练与未来实时推理共享的数据语义。

交付：

- 批处理 Provider、流式 Provider 契约，以及一个 A 股、一个期货样例适配器。
- Parquet 分区、DuckDB 查询和数据目录。
- 交易日历、复权、连续合约视图与质量报告。
- `Tick`、`Bar`、`FeatureFrame` 基础契约和 `event_time / available_time` 时态语义。
- as-of 查询、防未来数据泄漏检查和可重建特征快照。
- 数据中心 UI。

出口：相同数据和特征快照可以在不同设备通过用户自行准备的数据重建；批处理和流式数据遵循相同领域语义；Git 中只包含小型脱敏夹具。

完成证据：

- A 股 `600000.SSE` 与国内期货 `RB0.SHFE` 离线导入均通过端到端验收。
- 不可变清单、Parquet 文件与 SQLite 目录记录一致。
- as-of 查询和基线特征构建均约束 `event_time / available_time`，防泄漏回归通过。
- 相同输入、代码版本和参数重复构建得到相同 FeatureFrame 快照 ID。
- 数据中心用户流测试、TypeScript 检查和 Vite 构建通过。
- 仓库策略拒绝下载行情、数据库、Parquet、模型权重和运行状态目录。

## Phase 3A：东财国内真实行情（IN_PROGRESS）

目标：通过用户本机东财掘金终端取得 A 股、ETF、指数和具体月份期货合约的真实只读
行情，为后续在线特征、策略与 Paper 模拟建立可信输入。

交付：SDK 隔离桥、六个核心指数、50 标的订阅预算、本地持久化自选与分时、
状态/延迟/重连、凭据安全和聚合验收探针。自选只保存代码、顺序和已知名称，价格仍由
真实 Provider 取得。正式首页不保留模拟行情降级。真实交易时段 30 分钟验收通过前保持
`IN_PROGRESS`。

## Phase 3B：实时量化核心纵向切片

状态：**首个可运行切片已完成（2026-08-06）**

目标：先用确定、可审计的分钟级基线策略贯通“真实行情 → 在线特征 → 信号与抑制
→ 决策留痕 → 桌面展示”，再在相同契约上替换或叠加 AI/ML 模型。

已交付：

- `SignalFrame`、`DecisionRecord`、特征快照 ID 和信号有效期领域契约。
- 只使用已完成分钟线的实时特征构建，避免把未完成 K 线或未来数据带入决策。
- 分钟动量 + 均线位置 + 成交量放大的确定性基线引擎。
- 非实时行情、过期行情和样本不足时的 fail-closed 抑制/预热状态。
- 鉴权实时信号 API、10 秒轮询、桌面量化状态条和 BUY/SELL 图上标记。
- 每个结果均包含策略版本、特征版本、原因码、置信度、有效期与决策记录 ID。
- 行情展示层完成券商式收尾：分时累计均价，MA/BOLL 主图，
  VOL/MACD/KDJ/RSI 副图，十字光标价格与涨跌幅联动，以及独立量化图层开关。
- 指标、量化图层和行情请求相互隔离；量化接口失败时继续展示真实行情并明确标记不可用。

当前限制：

- 这是验证实时闭环和安全边界的 baseline，不声称具有稳定超额收益。
- `baseline-v1` 是 AstraQuant 自建的确定性规则基线，不是开源 AI 模型，也不是最终交易策略。
- 只输出观察提示，不连接交易账户、不发送委托，也不做融券或期货开空。
- 下一步进入 Phase 4A：使用版本化数据训练并评估 AI/ML 基线模型，再通过现有
  `SignalFrame` 契约进入在线影子模式。

## Phase 4A：AI 研究与回测闭环

目标：从版本化特征、模型训练到信号和可重复回测报告。

交付：

- 特征工程、标签、训练/验证切分和至少一个 AI 基线模型。
- `ModelArtifact`、模型注册、评估门槛、`SignalFrame` 和参数管理。
- 撮合、费用、滑点、组合与基准。
- 实验记录、模型比较、运行对比、解释和报告。
- 可选 Qlib Provider 原型。

出口：固定数据快照和模型版本可重现训练、预测与黄金回测；防泄漏测试和确定性回放通过。

## Phase 4B：实时 AI 信号与 Paper 模拟闭环

目标：验证实时行情、在线特征、模型推理、买卖点提示和虚拟组合，不连接真实交易账户。

交付：

- 行情回放、实时行情流、在线特征和 Paper 模拟引擎。
- 模型加载、在线推理、信号发布、延迟与漂移监控。
- 买入、卖出、减仓、止损、止盈和观望提示。
- 虚拟委托、成交、资金、持仓、风险提示和复盘。
- 断线、重复、乱序和重启测试。

出口：同一模型的离线/在线特征在相同截止时刻一致；连续模拟运行稳定，每条提示包含理由、置信度、风险、有效期和可追溯证据。

## Phase 5：外部手动交易辅助闭环

目标：帮助用户把 AI 提示安全地带到外部券商或期货软件，并把实际结果带回复盘；AstraQuant 不发送真实委托。

交付：

- 桌面通知、声音提醒、信号确认和过期处理。
- 可复制的标的、方向、参考区间、仓位、止损和止盈建议。
- 外部交易前检查清单，显式展示交易时段、涨跌停、夜盘、平今和保证金语义。
- 用户手工录入或文件导入实际成交，用于信号归因和交易日志。
- 模型版本锁定、推理降级、暂停提醒和人工确认流程。
- 提醒到人工执行的延迟、滑点和偏差分析。

出口：AstraQuant 在没有券商/CTP 凭据和委托能力的情况下，完成实时提示、用户确认、外部执行记录和复盘闭环。

## Phase 6：深化与扩展

候选方向：

- 因子库、深度学习、强化学习和组合优化。
- 本地大语言模型研究助手、自然语言实验编排和智能复盘。
- 多模型集成、模型漂移、影子模式与自动再训练审批。
- 可选只读文件导入和标准化交易日志，不增加真实下单能力。
- 私有远程执行节点与多设备只读监控。
- 插件 SDK、主题包和原创角色助手。
- 性能数据证明必要后引入 Rust 热点模块。
