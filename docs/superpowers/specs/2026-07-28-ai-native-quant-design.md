# AstraQuant AI 原生双循环设计

日期：2026-07-28
状态：已获用户方向确认，待书面审阅

## 1. 决策

AstraQuant 明确定位为面向中国 A 股与国内期货的本地优先、AI 主导量化研究与交易平台。

“AI 主导”表示 AI 是特征发现、模型训练、信号生成、市场状态识别、组合辅助和复盘解释的核心能力，而不是在传统量化终端末端附加聊天窗口。它不表示把数据核算、风险规则、订单状态或交易账户交给不可审计的模型控制。

平台采用推荐的双循环：

```text
离线研究循环
历史快照 → 时态对齐 → FeatureFrame → 模型训练/评估
→ ModelArtifact → SignalFrame → 确定性回测 → 模型发布

在线交易循环
实时 Tick/Bar → 在线 FeatureFrame → 已发布模型推理
→ SignalFrame/目标仓位 → 确定性风控 → OMS
→ Paper/Live Gateway → 委托/成交/持仓回报 → 监控与复盘
```

## 2. 方案比较

### 方案 A：传统量化优先，后期附加 AI

优点是早期实现简单，缺点是数据版本、特征时态、模型登记和在线推理往往需要后补，容易推翻数据层。拒绝。

### 方案 B：端到端实时 AI 直接决策和下单

优点是概念统一，缺点是难以复现、解释、测试和满足交易安全要求，也会把大模型延迟与不确定性放入关键执行路径。拒绝。

### 方案 C：AI 主导研究与信号，确定性系统执行

离线训练和在线推理解耦，AI 通过版本化结构化契约参与决策，风控、OMS、对账和 Gateway 保持确定性。该方案兼顾 AI 能力、实时性、可重现性与安全性，已选用。

## 3. 核心契约

### 3.1 FeatureFrame

必须记录：

- 标的、频率和样本主键；
- `event_time`：市场事件发生时间；
- `available_time`：该信息在真实世界可被策略获得的时间；
- 特征定义版本和输入数据快照；
- 缺失、异常和数据质量状态。

任何离线训练或回测只能读取决策截止时间之前已经可用的数据。

### 3.2 ModelArtifact

必须记录：

- `model_id` 和不可变版本；
- 训练数据与特征快照；
- 代码、依赖、随机种子和参数；
- 训练/验证/测试时间窗口；
- 指标、风险摘要和发布状态；
- 本地权重文件哈希与兼容的输入/输出 Schema。

模型权重默认只保存在本机，不提交 Git。

### 3.3 SignalFrame

模型和规则策略统一输出结构化信号，不直接调用 Gateway。至少包含：

- 标的与决策时间；
- 预测、置信度或目标仓位；
- 模型和特征版本；
- 有效期与信号 Schema 版本；
- 解释摘要和质量状态。

SignalFrame 经过校验、组合、风控和订单规划后才能形成订单意图。

### 3.4 DecisionRecord

每次 Paper 或 Live 决策记录：

```text
data_snapshot_id
feature_snapshot_id
model_id / model_version
signal_id
risk_decision_ids
order_intent_ids
market_event_time
decision_time
gateway_result_ids
```

该记录用于回答“模型当时看到了什么、为什么产生信号、哪条风控放行或拒绝、最终发生了什么”。

## 4. 实时性

量化不等于所有策略都采用 Tick 或微秒频率。推理频率由策略声明：

- 日线/隔夜模型：盘后批处理，下一交易时段执行；
- 分钟策略：在已完成 K 线或固定调度点推理；
- Tick/盘口策略：由事件驱动引擎逐事件更新；
- 大语言模型：不进入低延迟订单热路径，只用于研究、解释或低频结构化建议。

Phase 2 定义批处理与流式数据的共同语义，Phase 4 才实现生产级实时行情、在线特征与 Paper 推理。这样不会过早搭建实盘链路，也不会让历史数据层阻碍未来实时交易。

## 5. AI 安全边界

以下能力必须保持确定性：

- 数据校验、时态对齐、复权和交易日历；
- 回测撮合、手续费、滑点、保证金和盈亏；
- 交易前/交易中风险规则；
- OMS、订单状态机、幂等、撤单和账户对账；
- Gateway 协议、凭据和紧急停止。

AI 或外部 Agent 不得：

- 直接持有交易 Gateway 凭据；
- 绕过 SignalFrame 和风险管线；
- 在输出无效、过期或无法解释时生成默认订单；
- 未经登记和发布就进入 Paper 或 Live；
- 自动把模型权重、训练数据或账户信息上传公共云。

## 6. 降级与故障处理

- 实时行情过期：暂停新信号，不用旧价格猜测。
- 在线特征缺失：拒绝该次推理或使用模型声明的显式缺失处理。
- 模型加载失败：保持 `MODEL_UNAVAILABLE`，不自动切换未批准模型。
- 输出 Schema 无效：记录失败并丢弃信号。
- 推理延迟超限：使信号过期，由策略声明是否进入安全的规则降级模式。
- LLM 服务不可用：不影响确定性回测、Paper/Live 引擎和人工交易监控。

## 7. 验证标准

- 防未来数据泄漏测试覆盖 `available_time` 和 as-of 查询。
- 固定数据、代码、参数和随机种子可重现预测摘要。
- 离线特征与逐事件在线特征在相同截止时间一致。
- 未登记、未批准或输入 Schema 不兼容的模型无法进入 Paper/Live。
- 任意 AI 输出均无法绕过风控直接创建 Gateway 委托。
- 每次模拟或实盘决策都能从 DecisionRecord 追溯完整证据链。

## 8. 阶段落点

- Phase 2：AI 可用数据、时态语义、FeatureFrame 和流式契约。
- Phase 3：模型训练、注册、SignalFrame、解释和黄金回测。
- Phase 4：实时行情、在线特征、在线推理和 Paper Trading。
- Phase 5：CTP/券商适配、模型发布门、实盘风控和人工启用。
- Phase 6：本地 LLM 助手、多模型集成、漂移监控和再训练审批。
