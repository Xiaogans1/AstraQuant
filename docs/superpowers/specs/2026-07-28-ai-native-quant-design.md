## 1. 决策

AstraQuant 明确定位为面向中国 A 股与国内期货的本地优先、AI 主导量化研究与实时决策辅助平台。

“AI 主导”表示 AI 是特征发现、模型训练、信号生成、市场状态识别、组合辅助和复盘解释的核心能力，而不是在传统量化终端末端附加聊天窗口。它不表示把数据核算或真实交易账户交给不可审计的模型控制。

产品不连接真实证券或期货账户，不保存券商、交易终端或 CTP 交易凭据，不向任何真实交易通道发送委托。AstraQuant 负责实时提示买点、卖点、减仓、离场和观察状态，并可在本地进行 Paper 模拟；用户始终在外部交易软件中人工确认和操作。

平台采用推荐的双循环：

```text
离线研究循环
历史快照 → 时态对齐 → FeatureFrame → 模型训练/评估
→ ModelArtifact → SignalFrame → 确定性回测 → 模型发布

在线决策循环
实时 Tick/Bar → 在线 FeatureFrame → 已发布模型推理
→ SignalFrame → 确定性提示校验 → UI/桌面通知
→ Paper 模拟 → 用户在外部软件人工交易
→ 可选人工成交记录 → 监控、归因与复盘
```

## 2. 方案比较

### 方案 A：传统量化优先，后期附加 AI

优点是早期实现简单，缺点是数据版本、特征时态、模型登记和在线推理往往需要后补，容易推翻数据层。拒绝。

### 方案 B：端到端实时 AI 直接决策并自动下单

优点是概念统一，缺点是难以复现、解释和测试，还要求产品接触交易账户与真实资金。与“仅提示、用户外部手动交易”的产品边界冲突，拒绝。

### 方案 C：AI 主导研究与信号，用户外部人工执行

离线训练和在线推理解耦，AI 通过版本化结构化契约参与决策；系统确定性地完成数据校验、信号校验、Paper 模拟和审计记录；真实买卖由用户在外部软件完成。该方案兼顾 AI 能力、实时性、可重现性、隐私与最终人工控制，已选用。

## 3. 核心契约

### 3.1 FeatureFrame

必须记录：

- 标的、频率和样本主键；
- `event_time`：市场事件发生时间；
- `available_time`：该信息在真实世界可被策略获得的时间；
- 特征定义版本和输入数据快照；
- 缺失、异常和数据质量状态。

任何离线训练或回测只能读取决策截止时间之前已经可用的数据。

### 3.2 ModelArtifact

必须记录：

- `model_id` 和不可变版本；
- 训练数据与特征快照；
- 代码、依赖、随机种子和参数；
- 训练/验证/测试时间窗口；
- 指标、风险摘要和发布状态；
- 本地权重文件哈希与兼容的输入/输出 Schema。

模型权重默认只保存在本机，不提交 Git。

### 3.3 SignalFrame

模型和规则策略统一输出结构化信号。至少包含：

- 标的与决策时间；
- 动作：`BUY`、`SELL`、`REDUCE`、`EXIT` 或 `HOLD`；
- 参考价格或价格区间、建议仓位与置信度；
- 止损、止盈、失效条件与风险提示；
- 模型和特征版本；
- 有效期与信号 Schema 版本；
- 解释摘要和质量状态。

`SignalFrame` 经过完整性、时效性、市场规则、组合暴露和提示频率校验后，才能显示、通知或进入 Paper 模拟。它永远不会转换为真实委托。

### 3.4 DecisionRecord

每次实时信号或 Paper 决策记录：

```text
data_snapshot_id
feature_snapshot_id
model_id / model_version
signal_id
advisory_check_ids
market_event_time
decision_time
notification_ids
user_acknowledged_at
paper_result_ids
manual_trade_record_id (optional)
```

该记录用于回答“模型当时看到了什么、为什么产生信号、哪条校验允许或抑制提示、Paper 结果如何、用户是否记录了外部人工交易”。人工成交记录只是复盘输入，不代表程序连接或控制交易账户。

## 4. 实时性

量化不等于所有策略都采用 Tick 或微秒频率。推理频率由策略声明：

- 日线/隔夜模型：盘后批处理，在下一交易时段提示；
- 分钟策略：在已完成 K 线或固定调度点推理；
- Tick/盘口策略：由事件驱动引擎逐事件更新；
- 大语言模型：不进入低延迟信号热路径，只用于研究、解释或低频结构化建议；低延迟模型使用本地已发布推理产物。

Phase 2 定义批处理与流式数据的共同语义，Phase 4 才实现生产级实时行情、在线特征与 Paper 推理。这样既不让历史数据层阻碍未来实时提示，也不会引入真实交易链路。

## 5. AI 安全边界

以下能力必须保持确定性：

- 数据校验、时态对齐、复权和交易日历；
- 回测撮合、手续费、滑点、保证金和盈亏；
- 信号时效、市场状态、建议仓位和组合暴露校验；
- Paper 虚拟委托、虚拟成交、持仓和资金核算；
- 通知去重、限频、确认状态和审计记录。

AI 或外部 Agent 不得：

- 获取或要求用户提供真实交易凭据；
- 绕过 `SignalFrame` 和提示校验；
- 在输出无效、过期或无法解释时生成默认买卖建议；
- 未经登记和发布就进入实时提示或 Paper；
- 自动把模型权重、训练数据或人工交易记录上传公共云；
- 调用外部交易软件接口、模拟用户点击或以其他方式发送真实委托。

## 6. 降级与故障处理

- 实时行情过期：暂停新信号，不用旧价格猜测。
- 在线特征缺失：拒绝该次推理或使用模型声明的显式缺失处理。
- 模型加载失败：保持 `MODEL_UNAVAILABLE`，不自动切换未批准模型。
- 输出 Schema 无效：记录失败并丢弃信号。
- 推理延迟超限：使信号过期，由策略声明是否进入安全的规则降级模式。
- LLM 服务不可用：不影响确定性回测、Paper 引擎、已发布本地模型推理和人工交易记录。

## 7. 验证标准

- 防未来数据泄漏测试覆盖 `available_time` 和 as-of 查询。
- 固定数据、代码、参数和随机种子可重现预测摘要。
- 离线特征与逐事件在线特征在相同截止时间一致。
- 未登记、未批准或输入 Schema 不兼容的模型无法进入实时提示或 Paper。
- 任意 AI 输出都只能产生结构化建议或 Paper 虚拟事件，系统不存在真实委托出口。
- 每次实时提示和模拟决策都能从 `DecisionRecord` 追溯完整证据链。
- 人工成交可手动录入或从本地文件导入，但不能反向触发真实交易。

## 8. 阶段落点

- Phase 2：AI 可用数据、时态语义、FeatureFrame 和流式契约。
- Phase 3：模型训练、注册、SignalFrame、解释和黄金回测。
- Phase 4：实时行情、在线特征、在线推理、提示校验和 Paper Trading。
- Phase 5：桌面通知、可复制交易建议、人工操作清单、人工成交记录与效果归因。
- Phase 6：本地 LLM 助手、多模型集成、漂移监控和再训练审批。
