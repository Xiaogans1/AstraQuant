# AstraQuant 本地自选持久化设计

**状态：** 已确认
**日期：** 2026-08-06
**范围：** Phase 3A 自选列表的本地持久化与重启恢复

## 1. 问题

当前自选只保存在 `SubscriptionBudget` 的进程内存中。关闭或重启 AstraQuant 后，用户添加
的股票、ETF 和具体月份期货合约全部消失。这不符合桌面行情终端的基本使用预期，也会
导致后续量化扫描、AI 情报和 Paper 模拟失去稳定观察池。

## 2. 目标

- 用户添加或删除自选后，立即保存到本机 SQLite。
- AstraQuant 重启时自动恢复自选代码、顺序和已知名称。
- 恢复后价格仍从东财实时行情重新取得，不持久化或伪造价格。
- 保持 34 个持久自选名额、6 个核心指数和 10 个临时分析槽位的现有配额边界。
- 无效或损坏的单条记录被隔离，不阻止程序启动，也不影响其他有效自选。
- 自选、SDK 路径等非秘密配置可存入 SQLite；Token 仍只保存在 Windows 凭据管理器。

## 3. 方案

新增 `market_watchlist.py`，把序列化、规范化和损坏记录隔离集中在一个模块。数据使用现有
`settings` 表中的 `market.watchlist` 键，以单行 JSON 原子更新：

```json
{
  "version": 1,
  "items": [
    {"instrument_id": "600000.SSE", "name": "浦发银行"}
  ]
}
```

`MarketDataService` 接收可选的 `SettingsStore`：

1. 构造时加载持久化记录并填充 `SubscriptionBudget`；
2. 添加自选成功后保存当前有序列表；
3. 删除自选后保存剩余列表；
4. 搜索得到的证券名称与代码一起保存；
5. 测试或不提供存储时继续使用纯内存模式。

生产启动由 `cli.py` 把现有 `TaskRepository` 传给行情服务。前端 API 契约不变，因此不需要
新增按钮、登录或云端账号。

## 4. 状态与错误处理

- 设置不存在：视为空自选，首次添加时创建。
- JSON 结构错误：视为空自选，不覆盖数据库，等待用户下一次有效增删后写入新版本。
- 单条代码无效：跳过该条，继续恢复其他记录。
- 重复代码：保留第一次出现的位置。
- 核心指数：不写入用户自选。
- 超过 34 条：按保存顺序恢复前 34 条，确保订阅预算不溢出。
- 连续期货或其他旧版无效记录：恢复时跳过；实时添加仍由现有 API 校验。

## 5. 验收

1. 添加带名称的自选后，新建行情服务实例能够恢复相同代码、名称和顺序。
2. 删除自选后再次重启不会恢复被删除项目。
3. 损坏、重复和超额数据不会导致启动失败。
4. SQLite 中不出现价格、Token、账号或密码。
5. 原有搜索、订阅配额、真实行情、分时和断线状态测试全部通过。
