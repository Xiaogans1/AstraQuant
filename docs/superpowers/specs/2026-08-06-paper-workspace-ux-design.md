# 模拟盘工作台体验重构设计

## 目标

把模拟盘从“开发参数面板”改成可直接使用的本地交易工作台。用户只需维护剩余现金和期初持仓，随后查看真实行情盯市、资产变化、策略状态与虚拟成交；内部仓位上限、建议数量等参数不再占据主界面。

模拟盘不是另一套行情软件，而是市场行情的“账户视角”。首页与模拟盘必须复用同一个标的工作台：同一套真实分时、K 线、指标和十字光标，在模拟盘上下文中额外叠加期初持仓、量化信号、虚拟成交点和持仓盈亏。

## 量化用户的信息优先级

主界面严格按用户真实决策顺序组织：

1. 账户当前赚亏、仓位和可用资金是否安全。
2. 当前持仓应继续持有、减仓还是退出。
3. 信号出现的原因、可信度、有效期和失效条件。
4. 买卖点位于真实 K 线的什么位置，信号是否实际执行。
5. 策略的日、月、年收益、最大回撤、胜率与稳定性。

证券代码、建议数量、单标的仓位上限、特征版本等工程参数不进入首要操作路径。它们由策略和风控引擎管理，只在高级设置或审计详情中按需查看。

## 资金语义

- 剩余现金：未投入持仓、可用于后续虚拟买入的资金，由用户直接修改。
- 持仓市值：真实行情对当前持仓的实时估值。
- 总资产：剩余现金与持仓市值之和。
- 权益基线：外部现金调整和期初持仓成本之和，用于计算策略收益；修改现金视为入金或出金，不计入策略盈亏。

## 信息架构

1. 账户概览：账户名称、真实行情状态、安全边界和五项资产指标。
2. 初始账户建立：用户连续录入自己持有的全部证券、数量、可用数量和平均成本；这是唯一的人工持仓操作。页面不提供手动虚拟买卖。
3. 持仓与标的工作台：点击任一持仓，在同页打开共享行情图；图上叠加该账户的量化信号和虚拟成交点。
4. 策略状态：普通模式只显示运行状态、覆盖范围、最近决策和启动/暂停操作。代码、建议数量、仓位上限和自动成交开关移出主界面。
5. 审计与绩效：订单、风控结果、虚拟成交和收益统计保持可追溯。

## 交易权责边界

- 用户负责：录入/修正剩余现金，录入全部期初持仓，选择需要查看的持仓，启动或暂停模拟策略。
- 量化核心负责：扫描持仓与自选池、计算建议数量、执行仓位与风险约束、产生买卖信号、完成虚拟成交。
- 主界面禁止：用户手工提交虚拟买单或卖单；这会污染策略绩效，也与自动量化的产品定位冲突。
- 未来实盘：共享相同的标的工作台和审计模型，但必须经过独立权限、风控与券商委托适配，不与当前模拟执行混用。

## 共享标的工作台

`MarketWorkspace` 是首页、模拟盘和未来实盘共用的行情组件。它接收标的行情、账户上下文与覆盖图层：

- `QUANT_SIGNAL`：策略产生的建议买卖点。
- `PAPER_FILL`：模拟盘实际成交点。
- `LIVE_FILL`：未来实盘成交点，当前不实现。
- `POSITION_BASELINE`：期初持仓成本与录入时间，用于账户语境展示。

模拟盘选择持仓后，工作台标题明确当前处于“模拟账户”上下文；图层可以开关，十字光标、周期和技术指标行为与首页完全一致。这样用户无需在两个页面重新学习图表，也不会出现数据表现不一致。

## 视觉方向

延续 AstraQuant 的浅色研究终端风格，但减少装饰性大字和过密的工程标签。使用清晰的 12/14/18/30px 字阶、统一的输入高度与等宽数据字体。核心识别点是“资产关系带”：总资产旁明确展示“现金 + 持仓市值”，让用户不需要理解账本术语。

布局在宽屏采用 `主内容 + 320px 操作坞`，窄屏自动变为上下结构。所有网格项使用 `min-width: 0`，表单控件使用 `width: 100%` 和 `box-sizing: border-box`，禁止按钮或输入框越过卡片边界。

## 交互规则

- 修改剩余现金后立即刷新账户、权益曲线和汇总数据，并显示明确的保存状态。
- 录入持仓成功后清理表单状态并刷新持仓和权益。
- 期初持仓录入支持连续添加；已有持仓的修正作为后续编辑能力，不伪装成量化成交。
- 策略区默认绑定当前持仓或自选池，不要求用户逐次填写证券代码和风控参数。
- 量化核心尚未进入持续运行阶段时，按钮文案明确为“运行一次检查”，避免伪装成已完成的自动策略服务。
- 用户点击持仓时，只切换共享行情工作台的账户上下文，不跳转到割裂的新页面。

## 验证

- API 测试验证现金调整不改变既有盈亏，并持久化到账本。
- React 测试验证现金编辑、低干预策略入口和核心文案。
- 类型检查、构建和全量测试通过。
- 在桌面应用中以常规窗口与全屏宽度截图检查，无溢出、遮挡或异常字号。
