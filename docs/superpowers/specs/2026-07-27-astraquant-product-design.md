# AstraQuant 产品与系统设计

日期：2026-07-27
状态：待用户书面审阅

## 1. 产品定义

AstraQuant 是一套 Windows 优先、本地优先的桌面量化平台。第一目标市场为中国 A 股和国内期货，面向单用户研究与交易场景。系统先建立数据、研究、回测、模拟、风控、执行、监控和复盘的最小闭环，再逐步加深功能。

第一版按单用户设计，但账户、工作区、运行任务和凭据均使用明确的所有者边界，避免未来增加多用户或私有远程节点时重写核心。

## 2. 成功标准

最小闭环完成时，用户能够：

1. 从至少一个公开数据适配器导入 A 股日线和国内期货日线/分钟线样例。
2. 查看数据版本、更新时间、缺失值和基本质量报告。
3. 创建策略或信号配置，并保存代码版本、参数和数据版本。
4. 运行确定性回测并查看收益、回撤、成交、持仓和风险指标。
5. 将同一交易策略运行于 Paper Trading。
6. 查看实时订单、成交、持仓、资金、日志和风险状态。
7. 触发限仓、日亏损限制、订单频率限制和紧急停止。
8. 从一次运行追溯到策略、参数、数据、事件和结果。

真实资金交易不作为第一个可运行版本的验收条件。CTP 实盘必须在 Paper Trading 闭环稳定、订单状态测试和账户对账完成后启用。

## 3. 产品形态

### 3.1 桌面端

- Tauri 提供安装、窗口、系统托盘、文件权限和本地进程管理。
- React + TypeScript 提供现代工作区和可复用 Web UI。
- 桌面端不直接实现交易逻辑，只调用本地控制服务。
- UI 崩溃或刷新不得中断独立运行的交易节点。

### 3.2 本地服务

- Python 控制服务仅监听 loopback 地址。
- 启动时生成短期会话令牌，桌面端通过受控通道获得令牌。
- 负责配置、任务编排、查询和状态聚合，不直接保存明文交易凭据。
- 长任务进入独立 Worker，避免阻塞 UI。

### 3.3 交易节点

- Paper、Backtest 和 Live 使用相同的订单、成交、持仓和风险领域模型。
- 每个真实交易 Gateway 在独立进程运行。
- 交易节点拥有持久化事件日志和重启恢复流程。
- 状态不确定时默认拒绝新订单，并要求先完成账户与订单对账。

## 4. 逻辑模块

```text
astraquant-domain       领域对象、事件、订单状态机、时钟
astraquant-data         数据目录、质量、版本、Parquet 与 DuckDB
astraquant-research     因子、信号、实验和可选 Qlib Provider
astraquant-backtest     撮合、费用、滑点、组合与回测报告
astraquant-execution    Paper/Live 执行、订单路由和账户对账
astraquant-risk         交易前、交易中、账户级风险规则
astraquant-adapters     数据源、vn.py/CTP 和未来券商适配器
astraquant-observability 日志、指标、审计与告警
astraquant-api          本地控制 API 和任务编排
astraquant-desktop      Tauri 外壳
astraquant-ui           React 工作区、主题和图表
```

模块通过公开接口和版本化事件通信，不导入其他模块的内部实现。

## 5. 研究与交易的统一边界

研究和实时交易不强行使用完全相同的计算方式：

- 因子与机器学习研究使用批处理数据，输出版本化的 `SignalFrame`。
- 事件驱动策略消费行情或 `SignalFrame`，输出目标仓位或订单意图。
- 回测、Paper 和 Live 复用事件驱动策略、风控与订单状态机。

这样既保留 Qlib 类批量研究效率，也避免把未来数据处理逻辑误带入实时交易。

每次运行记录：

```text
run_id
strategy_revision
parameters
data_snapshot_id
engine_version
environment
started_at / finished_at
result_artifact_ids
```

## 6. 数据设计

### 6.1 存储职责

- Parquet：行情、因子、信号和大规模回测序列。
- DuckDB：本地分析查询和跨 Parquet 视图。
- SQLite：项目、任务、配置、运行、订单索引和迁移版本。
- 追加式事件文件：关键订单、成交、风险和状态转换审计。
- Windows Credential Manager：数据商、券商和 CTP 密钥。

### 6.2 数据目录

数据按 `market / asset_class / frequency / trading_date` 分区。数据快照记录来源、拉取时间、适配器版本、复权方式、交易日历和质量摘要。

### 6.3 国内市场语义

领域模型必须显式支持：

- A 股交易日历、停牌、涨跌停、复权、T+1 和最小交易单位。
- 期货交易日与自然日差异、夜盘、合约乘数、保证金和手续费。
- 主力/连续合约只用于研究视图，真实订单必须映射到具体可交易合约。
- 开仓、平仓、平今等国内期货语义由适配层显式转换。

## 7. 订单、执行与风险

### 7.1 订单状态

订单状态转换必须是显式状态机。所有命令带全局唯一 `client_order_id`，重复请求必须幂等。外部 Gateway 回报映射成内部事件，不允许 UI 直接改写订单状态。

### 7.2 风控管线

基础规则包括：

- 单笔数量和金额上限。
- 标的、策略和账户的最大仓位。
- 最大日内亏损和最大回撤阈值。
- 单位时间订单与撤单频率。
- 价格偏离、无行情、过期行情和交易时段检查。
- Paper/Live 环境隔离。
- 全局与账户级紧急停止。

风险拒绝必须记录规则、输入、阈值和时间，且可在 UI 中解释。

### 7.3 重启与对账

交易节点启动后先读取本地快照与事件，再向 Gateway 查询资金、持仓、活动订单和当日成交。完成差异处理前保持 `RECONCILING` 状态并禁止新订单。

## 8. UI 与主题

### 8.1 核心工作区

- 数据中心：数据源、数据集、质量和更新任务。
- 研究中心：因子、信号、Notebook/脚本入口和实验记录。
- 回测中心：参数、任务队列、指标、图表和成交分析。
- 交易中心：行情、订单、成交、持仓、资金和策略运行状态。
- 风险中心：规则、暴露、告警和紧急停止。
- 复盘中心：运行对比、归因、交易日志和策略版本。

### 8.2 主题架构

主题使用设计令牌定义颜色、字体、圆角、阴影、透明度、背景、图表色板、动画和角色资源。

内置主题：

- `Astra Minimal`
- `Astra Light`
- `Nebula Boy`
- `Terminal Pro`

动漫主题采用原创、授权或可验证生成来源的清爽少年角色，不使用版权不明的动漫角色。角色和动画可完全关闭。用户背景只保存在本机。

实盘状态、风险等级、买卖方向、紧急停止和关键确认使用独立安全令牌，普通主题不能覆盖。

## 9. 错误处理与可观测性

- 每个任务拥有 `correlation_id`，跨 UI、API、Worker 和 Gateway 关联日志。
- 用户错误给出可操作说明；系统错误保留技术细节和堆栈到本地日志。
- 数据导入采用可恢复批次，失败不发布不完整快照。
- 回测任务失败不污染已完成结果。
- Gateway 断线进入降级状态，暂停新订单并保留撤单/查询能力的实际状态说明。
- 日志、指标和事件均有保留策略，默认不上传远程服务。

## 10. 测试策略

- 单元测试：领域对象、订单状态机、费用、滑点和风险规则。
- 属性测试：订单状态转换、金额和持仓不变量。
- 合约测试：所有数据 Provider 和交易 Gateway 执行同一组接口测试。
- 确定性回放：同一数据、策略和配置产生相同事件摘要。
- 黄金回测：固定小数据集验证收益、成交和持仓结果。
- 集成测试：桌面端、本地 API、Worker、Paper Gateway 的完整流程。
- 故障测试：断线、重复回报、乱序事件、进程重启和对账差异。
- UI 测试：风险操作、实盘标识、主题切换和可访问性。
- 打包测试：干净 Windows 环境安装、升级、卸载和本地数据保留。

## 11. GitHub 与多端协作

Git 保存源代码、文档、接口契约、数据库迁移、主题定义、锁文件、CI 和小型脱敏测试夹具。Git 不保存市场数据、密钥、日志、本地数据库、回测产物、模型权重、用户背景或上游研究仓库。

初始设计文档可直接建立 `main`。进入实现后使用短生命周期功能分支和 Pull Request。自动提交只发生在一个可验证的逻辑单元完成后；测试失败、包含秘密或存在未说明第三方代码时禁止自动推送。

完整规则见 `docs/governance/git-workflow.md`。

## 12. 非目标

第一阶段不实现：

- 高频和微秒级交易。
- 所有券商、数据商和交易所接口。
- 多机构、多租户与复杂权限。
- 策略市场、跟单、收费和社区。
- 默认启用真实资金自动交易。
- 将用户数据上传到公共云。

## 13. 决策摘要

1. Windows 桌面优先，Tauri + React + Python。
2. 单用户、本地优先，但保留远程私有节点和多用户边界。
3. 研究管线与事件驱动交易核心分层。
4. Paper 闭环先于 CTP 实盘。
5. 使用 AstraQuant 自有领域模型，通过适配器接入外部生态。
6. UI 支持专业默认主题与可关闭的原创动漫主题。
7. 代码与文档进入 GitHub，任何私人数据和运行产物留在本地。
