# AstraQuant 产品与系统设计

日期：2026-07-28
状态：已确认，持续演进

## 1. 产品定义

AstraQuant 是一套 Windows 优先、本地优先、AI 主导的桌面量化研究与实时决策辅助平台。第一目标市场为中国 A 股和国内期货，面向单用户研究、模拟与人工交易辅助场景。AI 不是附加聊天功能，而是特征发现、模型训练、信号生成、市场状态识别、组合辅助和复盘解释的核心能力。

平台采用离线研究训练与在线实时推理组成的双循环架构。AI 输出版本化的特征、预测和结构化买卖建议；数据一致性、回测核算、提示校验、Paper 模拟和审计记录保持确定性、可测试和可追溯。

真实交易的产品边界是永久性的：AstraQuant 不连接真实证券或期货账户，不保存交易凭据，不向券商、期货交易通道或外部交易软件发送委托。用户根据提示在外部软件中人工确认和操作。第一版按单用户设计，但工作区、运行任务、数据源凭据和本地数据均使用明确的所有者边界，避免未来增加多用户或私有远程计算节点时重写核心。

## 2. 成功标准

最小闭环完成时，用户能够：

1. 从至少一个公开数据适配器导入 A 股日线和国内期货日线/分钟线样例。
2. 查看数据版本、更新时间、缺失值和基本质量报告。
3. 创建策略或信号配置，并保存代码版本、参数和数据版本。
4. 从版本化特征快照训练至少一个 AI 基线模型，并登记训练数据、代码、参数、指标和模型产物。
5. 将模型输出转换为可审计的 `SignalFrame`，运行确定性回测并查看收益、回撤、成交、持仓和风险指标。
6. 将同一模型和信号契约运行于实时 Paper Trading。
7. 查看实时行情、模型推理、买卖建议、Paper 虚拟成交/持仓/资金、日志和风险提示。
8. 对过期行情、异常置信度、建议仓位、组合暴露和提示频率执行确定性校验。
9. 从一次决策追溯到数据快照、特征、模型、参数、信号、提示校验、Paper 结果和可选人工成交记录。

真实资金交易接入不属于任何阶段的产品目标。Paper Trading 用于验证模型与建议，不是通往程序自动交易的过渡步骤。

## 3. 产品形态

### 3.1 桌面端

- Tauri 提供安装、窗口、系统托盘、文件权限和本地进程管理。
- React + TypeScript 提供现代工作区和可复用 Web UI。
- 桌面端不直接实现模型训练和 Paper 核算，只调用本地控制服务。
- UI 崩溃或刷新不得破坏已持久化任务、实时信号与 Paper 状态。

### 3.2 本地服务

- Python 控制服务仅监听 loopback 地址。
- 启动时生成短期会话令牌，桌面端通过受控通道获得令牌。
- 负责配置、任务编排、查询和状态聚合；数据源密钥存入操作系统凭据库。
- 长任务进入独立 Worker，避免阻塞 UI。

### 3.3 实时信号与 Paper 节点

- 回测和 Paper 使用相同的虚拟委托、成交、持仓、费用和风险核算模型。
- 实时行情、在线特征、模型推理和提示分发可在独立 Worker 运行。
- 节点拥有持久化事件日志和重启恢复流程。
- 数据、模型或时钟状态不确定时默认抑制新提示，并在界面明确说明原因。
- 节点不包含真实交易适配器，也不接受真实账户凭据。

## 4. 逻辑模块

```text
astraquant-domain       领域对象、事件、信号状态和时钟
astraquant-data         数据目录、质量、版本、Parquet 与 DuckDB
astraquant-research     特征、实验、标签和可选 Qlib Provider
astraquant-ai           模型训练、注册、推理、评估和漂移监控
astraquant-backtest     撮合、费用、滑点、组合与回测报告
astraquant-paper        Paper 虚拟委托、成交、持仓和资金核算
astraquant-advisory     信号校验、通知、人工确认和交易记录
astraquant-risk         建议仓位、组合暴露与 Paper 风险规则
astraquant-adapters     历史与实时市场数据适配器
astraquant-observability 日志、指标、审计与告警
astraquant-api          本地控制 API 和任务编排
astraquant-desktop      Tauri 外壳
astraquant-ui           React 工作区、主题和图表
```

模块通过公开接口和版本化事件通信，不导入其他模块的内部实现。

## 5. AI 研究与实时决策的统一边界

研究和实时决策不强行使用完全相同的计算方式：

- 离线 AI 研究使用版本化批处理数据和 `FeatureFrame`，产出可登记的 `ModelArtifact`。
- 在线推理消费实时 `Tick`、`Bar` 或已物化的在线特征，输出版本化 `SignalFrame`。
- 大语言模型可以生成研究方案、代码草案和结构化决策建议，但其输出必须经过 Schema 校验、回测或提示校验。
- 事件驱动策略消费行情或 `SignalFrame`，输出带有效期、价格区间、建议仓位、止损止盈和解释的交易建议。
- 回测和 Paper 复用事件驱动策略、费用、滑点、虚拟成交与风险核算。
- 实时建议只显示、通知或进入 Paper 模拟，不存在转换为真实委托的接口。

这样既保留 Qlib 类批量研究效率和 AI 的非线性建模能力，也避免未来数据泄漏、不可复现推理，并把真实资金的最终控制权完整留给用户。

每次运行记录：

```text
run_id
strategy_revision
parameters
data_snapshot_id
engine_version
environment
started_at / finished_at
result_artifact_ids
feature_snapshot_id
model_id / model_version
signal_schema_version
inference_mode
```

## 6. 数据设计

### 6.1 存储职责

- Parquet：行情、因子、信号和大规模回测序列。
- DuckDB：本地分析查询和跨 Parquet 视图。
- SQLite：项目、任务、配置、运行、Paper 索引、人工交易记录和迁移版本。
- 追加式事件文件：关键信号、提示校验、Paper 事件和状态转换审计。
- Windows Credential Manager：仅保存需要鉴权的数据源密钥。

### 6.2 数据目录

数据按 `market / asset_class / frequency / trading_date` 分区。数据快照记录来源、拉取时间、适配器版本、复权方式、交易日历和质量摘要。

所有可用于训练或在线推理的数据都必须包含 `event_time`、`available_time` 和来源版本。特征构建必须采用 as-of 语义，禁止使用在决策时刻尚不可获得的数据。历史批处理 Provider 与实时流式 Provider 共享标准化 `Tick`、`Bar` 和标的契约，但不强行共享传输实现。

### 6.3 国内市场语义

领域模型必须显式支持：

- A 股交易日历、停牌、涨跌停、复权、T+1 和最小交易单位。
- 期货交易日与自然日差异、夜盘、合约乘数、保证金和手续费。
- 主力/连续合约可用于研究，但面向用户的实时建议必须标明具体合约或明确提示需要人工换月判断。
- 开仓、平仓、平今等国内期货语义在建议和 Paper 模拟中显式表达，避免用户误读。

## 7. 信号、Paper 模拟与人工交易辅助

### 7.1 信号生命周期

每个信号拥有全局唯一 `signal_id`，并按 `CREATED → VALIDATED/SUPPRESSED → NOTIFIED → ACKNOWLEDGED/EXPIRED` 显式流转。相同模型、标的、决策时刻和输入快照不得重复提示。UI 只能记录确认、忽略或备注，不能篡改模型原始输出。

### 7.2 提示校验与风险说明

基础规则包括：

- 建议数量、金额和仓位上限。
- 标的、策略和 Paper 组合的最大暴露。
- 基于 Paper 或用户手动录入记录的亏损与回撤提醒。
- 单位时间提示频率和重复信号抑制。
- 价格偏离、无行情、过期行情和交易时段检查。
- 回测、Paper 与实时提示环境隔离。
- 一键静默实时提示与模型停用。

提示放行或抑制必须记录规则、输入、阈值和时间，且可在 UI 中解释。仓位、止损和止盈均是建议，不伪装成已在外部交易软件生效的保护措施。

### 7.3 外部人工交易交接

提示卡片提供可复制的标的、方向、参考价格区间、建议仓位、止损、止盈、有效期和风险说明，并明确显示“需在外部交易软件人工操作”。用户可勾选已查看、已忽略或已在外部操作，也可手动录入或从本地文件导入实际成交用于归因。系统不读取交易终端、不模拟用户点击、不验证外部委托是否成功。

Paper 节点重启后从本地快照与事件恢复虚拟资金、持仓和活动虚拟委托；恢复完成前不推进 Paper 撮合，但不影响历史研究。

## 8. UI 与主题

### 8.1 核心工作区

- 数据中心：数据源、数据集、质量和更新任务。
- AI 研究中心：特征、标签、模型、Notebook/脚本入口、实验记录和模型比较。
- 模型中心：模型注册、版本、评估、发布状态、在线推理和漂移告警。
- 回测中心：参数、任务队列、指标、图表和成交分析。
- 信号中心：实时行情、模型建议、解释、有效期、确认状态和桌面通知。
- Paper 中心：虚拟委托、成交、持仓、资金和策略运行状态。
- 风险中心：提示校验、建议暴露、告警和模型静默。
- 复盘中心：运行对比、归因、人工交易记录和策略版本。

### 8.2 主题架构

主题使用设计令牌定义颜色、字体、圆角、阴影、透明度、背景、图表色板、动画和角色资源。

内置主题：

- `Astra Minimal`
- `Astra Light`
- `Nebula Boy`
- `Terminal Pro`

动漫主题采用原创、授权或可验证生成来源的清爽少年角色，不使用版权不明的动漫角色。角色和动画可完全关闭。用户背景只保存在本机。

实时数据状态、信号新鲜度、风险等级、买卖方向、Paper 标识和“外部人工操作”提示使用独立安全令牌，普通主题不能覆盖。

## 9. 错误处理与可观测性

- 每个任务拥有 `correlation_id`，跨 UI、API、Worker、数据 Provider 和 Paper 引擎关联日志。
- 用户错误给出可操作说明；系统错误保留技术细节和堆栈到本地日志。
- 数据导入采用可恢复批次，失败不发布不完整快照。
- 模型训练、发布和在线推理拥有独立 `correlation_id`，推理失败时不得生成隐式默认建议。
- 在线特征过期、模型版本缺失或输出不符合 Schema 时拒绝该次信号，并记录可解释原因。
- 回测任务失败不污染已完成结果。
- 实时数据 Provider 断线进入降级状态，抑制依赖该数据的新提示并明确展示数据陈旧状态。
- 日志、指标和事件均有保留策略，默认不上传远程服务。

## 10. 测试策略

- 单元测试：领域对象、信号生命周期、Paper 费用、滑点和提示校验规则。
- 属性测试：信号状态转换、Paper 金额和持仓不变量。
- 合约测试：所有历史与实时数据 Provider 执行同一组接口测试。
- 确定性回放：同一数据、策略和配置产生相同事件摘要。
- 黄金回测：固定小数据集验证收益、成交和持仓结果。
- 防泄漏测试：验证 `available_time`、训练/验证切分和 as-of 特征不会读取未来信息。
- 模型测试：固定数据和模型版本产生相同预测摘要，评估指标满足发布门槛。
- 在线等价测试：离线特征与逐事件在线特征在相同截止时刻得到一致结果。
- 集成测试：桌面端、本地 API、Worker、实时提示和 Paper 引擎的完整流程。
- 故障测试：数据断线、重复信号、乱序事件、进程重启和 Paper 恢复差异。
- 边界测试：仓库与运行时不存在真实交易适配器、真实交易凭据字段或发送委托能力。
- UI 测试：提示确认、Paper 标识、外部人工操作说明、主题切换和可访问性。
- 打包测试：干净 Windows 环境安装、升级、卸载和本地数据保留。

## 11. GitHub 与多端协作

Git 保存源代码、文档、接口契约、数据库迁移、主题定义、锁文件、CI 和小型脱敏测试夹具。Git 不保存市场数据、密钥、日志、本地数据库、回测产物、模型权重、用户背景或上游研究仓库。

初始设计文档可直接建立 `main`。进入实现后使用短生命周期功能分支和 Pull Request。自动提交只发生在一个可验证的逻辑单元完成后；测试失败、包含秘密或存在未说明第三方代码时禁止自动推送。

完整规则见 `docs/governance/git-workflow.md`。

## 12. 非目标

不实现：

- 高频和微秒级交易。
- 真实券商、期货交易通道和交易所委托接口。
- 多机构、多租户与复杂权限。
- 策略市场、跟单、收费和社区。
- 读取真实交易账户、持仓、资金、委托或成交。
- 发送真实委托、自动点击外部交易软件或任何形式的自动交易。
- 将用户数据上传到公共云。
- 允许大语言模型、外部 Agent 或任何内部模块发送真实委托。

## 13. 决策摘要

1. Windows 桌面优先，Tauri + React + Python。
2. 单用户、本地优先，但保留远程私有节点和多用户边界。
3. 产品采用离线 AI 研究训练与在线实时推理的双循环架构。
4. AI 主导研究、信号与决策辅助，确定性系统主导数据一致性、提示校验、Paper 核算和审计。
5. 程序只提示与模拟；用户始终在外部交易软件人工操作，产品永不接入真实委托链路。
6. 使用 AstraQuant 自有领域模型，通过适配器接入外部生态。
7. UI 支持专业默认主题与可关闭的原创动漫主题。
8. 代码与文档进入 GitHub，任何私人数据和运行产物留在本地。
