# AstraQuant 东财实时行情与全球夜盘雷达设计

**状态：** 已确认，待实施计划

**日期：** 2026-08-05

**产品边界：** 本地优先、只读行情、AI 辅助决策、用户自行在外部交易软件下单

## 1. 决策摘要

AstraQuant 下一阶段不再以导入历史数据或开发模拟行情作为用户主流程。桌面端启动后应直接连接用户本机的东财掘金量化终端，展示真实的中国 A 股、ETF、指数及后续国内期货行情。

本设计作出以下决定：

1. 国内实时行情首选用户已经安装并验证的东财掘金 Python SDK `gm`。
2. 首页固定内置 6 个核心指数，不要求用户先添加自选。
3. 东财免费版最多同时订阅 50 个标的，采用显式配额管理。
4. 真实数据不可用时，不使用模拟价格、历史价格或硬编码数字填充页面。
5. DeepSeek 不产生价格、不直接决定买卖点，只解释经验证的行情、量化特征和情报证据。
6. 美股盘前、盘中、盘后行情需要独立的海外数据源，作为 Phase 3B 实施；国内实时行情不得因此延期。
7. 底层从第一天采用多数据源 Provider 架构，使 Eastmoney 和后续 Alpaca 可以共同工作。

## 2. 用户场景

### 2.1 国内交易时段

用户启动 AstraQuant 和东财掘金终端后，首页自动显示：

- 6 个核心指数的真实点位、涨跌幅、更新时间和分时走势；
- 系统内置观察池与用户自选的真实行情；
- 当前行情连接、延迟和数据质量状态；
- 仅基于观察池的量化候选；
- 有证据和时间戳的 AI 市场解读。

用户点击股票、ETF、指数或期货后进入详情工作区，查看分时、量化特征、风险状态、AI 情报和后续 Paper 模拟入口。

### 2.2 国内非交易时段

首页显示最后一次成功取得的真实收盘快照，并明确标记“上一交易日收盘”或“行情已停止更新”。不得把收盘快照标记为实时行情。

### 2.3 美股夜间时段

在 Phase 3B 完成后，首页或独立“全球夜盘”工作区显示美股主要 ETF、行业代理和 AstraQuant 自研主题篮子，帮助用户判断海外风险偏好及其对下一交易日 A 股的可能影响。

## 3. 首页信息架构

首页采用三层市场观察体系。

### 3.1 核心指数

固定内置以下 6 个指数：

| 指数 | 东财代码 | 观察目的 |
| --- | --- | --- |
| 上证指数 | `SHSE.000001` | 沪市整体状态 |
| 深证成指 | `SZSE.399001` | 深市整体状态 |
| 创业板指 | `SZSE.399006` | 成长风格 |
| 科创50 | `SHSE.000688` | 科技创新风格 |
| 沪深300 | `SHSE.000300` | 大盘核心资产 |
| 中证1000 | `SZSE.399852` | 小盘风格 |

核心指数属于系统维护的市场基准：

- 首次启动即存在；
- 不占用用户自选名额；
- 不由 DeepSeek 添加、删除或替换；
- 标记“指数 · 不可直接交易”；
- 可关联对应 ETF，但不能把指数价格当作 ETF 价格。

上证50、中证500、国证2000、红利指数及主题指数进入系统指数库，可被量化层选入“今日关注”，但不永久占据首页顶部。

### 3.2 今日关注

“今日关注”最多展示 3 个标的，来源可以是系统指数库、ETF 或观察池中的股票。选择过程分为两层：

1. 本地量化引擎根据真实行情计算趋势、相对强弱、成交额变化、波动率和多周期动量；
2. DeepSeek 基于量化结果和已采集的新闻证据生成解释、风险提示和关注理由。

DeepSeek 不能绕过白名单选择任意证券，也不能修改数值字段。没有在线模型、情报不足或响应校验失败时，该区域显示“AI 分析暂不可用”，量化评分仍可独立存在。

### 3.3 我的自选

用户可以添加股票、ETF、指数和具体月份的期货合约。用户自选与系统内置内容分开管理，删除自选不会影响核心指数。

## 4. 数据源架构

```text
Desktop UI
   |
Local Market API
   |
MarketDataService
   |-- SubscriptionBudget
   |-- SnapshotStore
   |-- DataQualityMonitor
   `-- MarketDataProvider
       |-- EastmoneyProvider    Phase 3A
       `-- AlpacaProvider       Phase 3B
```

### 4.1 统一 Provider 契约

数据源适配器必须提供：

- `provider_id` 与显示名称；
- 支持的市场、品种、频率和交易时段；
- 连接、断开、重连和健康状态；
- 订阅、取消订阅和当前订阅集合；
- Tick、分钟 Bar、快照和错误事件；
- 数据源时间、接收时间、质量状态和是否为衍生数据。

上层界面不得依赖东财或 Alpaca 原始字段。

### 4.2 EastmoneyProvider

Phase 3A 使用：

`D:\AstraQuantData\Eastmoney\PythonSDK\Scripts\python.exe`

以及已安装的 `gm` SDK。SDK、行情缓存、Token、账号和终端数据均保存在仓库之外。

EastmoneyProvider 负责：

- 将东财代码转换为 AstraQuant 统一 Instrument ID；
- 接收指数、股票、ETF 和后续具体月份期货合约行情；
- 处理约 3 秒 Tick 更新节奏和 60 秒以上指数 Bar；
- 维护连接状态、最后事件时间和错误分类；
- 将凭据留在本机配置或安全存储中，不通过 API 返回给前端。

### 4.3 50 标的订阅配额

初始配额建议：

| 类别 | 配额 | 说明 |
| --- | ---: | --- |
| 核心指数 | 6 | 始终订阅 |
| 用户及系统观察池 | 34 | 股票、ETF、指数、期货 |
| 临时分析槽位 | 10 | 当前详情、今日关注和短期主题 |

规则：

- 配额在本地集中管理，不允许多个模块各自偷偷订阅；
- 超额时先释放最久未使用的临时槽位；
- 永不自动移除核心指数和用户固定标的；
- 无法腾出空间时明确提示，不静默漏数据；
- 期货连续合约先解析为实际月份合约，再进行实时订阅。

## 5. 真实数据与状态语义

所有行情卡片必须显示数据状态：

| 状态 | 含义 | UI 行为 |
| --- | --- | --- |
| `LIVE` | 交易时段内正常收到事件 | 显示实时行情和更新时间 |
| `STALE` | 超过允许时间未更新 | 保留最后真实值，显示延迟警告 |
| `CLOSED` | 市场已收盘 | 显示最后收盘快照 |
| `CONNECTING` | 正在连接 | 显示骨架与连接状态，不显示假值 |
| `UNAVAILABLE` | 从未成功取得真实数据 | 显示暂无真实数据 |
| `ERROR` | 数据源或权限错误 | 显示可操作的错误说明 |

开发模拟数据只允许存在于测试、Story 或明确标记的开发演示入口。正式首页默认禁止回退到模拟数据。

市场宽度、全市场涨跌家数和全市场扫描需要全市场数据权限。当前权限不足时必须显示“当前数据源不支持”，不能用观察池数据冒充全市场。

## 6. AI 与量化职责边界

```text
真实行情和本地历史数据
        |
确定性特征与策略规则
        |
结构化 SignalCandidate
        |          新闻与情报证据
        |                 |
        `------> DeepSeek 解释与策略草案
                         |
                  Schema/白名单/风控校验
                         |
                    用户可见建议
```

### 6.1 量化核心负责

- 技术特征、相对强弱、波动率和量价关系；
- 信号候选、止损失效条件和风险约束；
- Paper 虚拟盘撮合与收益统计；
- 所有数值计算和可重复验证。

### 6.2 DeepSeek 负责

- 归纳新闻、政策、公告和市场情绪；
- 解释量化结果及其可能原因；
- 生成“今日关注”和盘前/盘中策略草案；
- 给出证据、时间戳、置信度和反例风险。

DeepSeek 不负责伪造实时数据、直接修改持仓、绕过风控或自动向真实账户下单。

## 7. 全球夜盘雷达（Phase 3B）

东财 `gm` 不承担美股行情。Phase 3B 新增独立 `AlpacaProvider`，首期使用少量透明的 ETF 代理：

- 市场：`SPY`、`QQQ`、`DIA`、`IWM`；
- 行业：`SMH`/`SOXX`、`XLK`、`XLF`、`XLE`；
- 商品代理：`GLD`、`USO`；
- 后续按需要加入其他经过审核的 ETF。

免费开发档只使用其允许的 IEX 实时覆盖，并在 UI 明确标记数据源及覆盖范围；不得称为美国全市场完整行情。需要完整 SIP 行情时由用户选择付费数据方案。

### 7.1 自研主题篮子

截图中“AI算力、CPO、商业航天、机器人”等类别将作为 AstraQuant 自研主题指标，而不是伪装成官方指数。每个主题必须保存版本化定义：

- 成分证券；
- 权重和再平衡规则；
- 计算基准；
- 数据源；
- 更新时间；
- 个股贡献度。

UI 使用“自研主题指标”标签，并允许用户展开查看计算依据。

### 7.2 海外到 A 股映射

跨市场分析流程：

1. 计算海外 ETF 和主题篮子的真实涨跌及异常强弱；
2. 结合汇率、商品、国内指数和前一交易日结构；
3. 使用经过验证的历史样本计算相关性与条件概率；
4. DeepSeek 结合当日新闻解释可能的传导路径；
5. 输出次日 A 股“观察计划”，而非保证性预测。

## 8. 本地数据、安全与仓库规则

- 行情缓存和数据库默认保存在 `D:\AstraQuantData` 或系统应用数据目录；
- `.env`、Token、账号、密码、终端缓存和原始行情包禁止提交 Git；
- Git 仓库只保存代码、无敏感信息的配置模板、测试夹具和聚合验证报告；
- 本地 API 只监听 loopback，并继续使用会话鉴权；
- 当前版本只读，不暴露账户、委托、撤单或真实交易接口。

## 9. 错误处理

- 东财终端未启动：提示启动终端并重试；
- SDK 不可导入：显示实际解释器路径和修复建议，但不暴露凭据；
- 行情权限不足：按品种和接口区分错误，不伪装为网络问题；
- 连接中断：指数退化为 `STALE`，暂停生成新的盘中信号；
- 单标的解析失败：隔离该标的，其他订阅继续运行；
- DeepSeek 调用失败：保留真实行情和量化结果，仅隐藏 AI 解释；
- 海外数据源未配置：全球夜盘显示“尚未连接”，不影响国内行情。

## 10. 测试与验收

### 10.1 自动化测试

- 东财原始事件到统一 Tick/Bar 的映射测试；
- 6 个核心指数配置与不可删除规则；
- 50 标的配额、临时槽位淘汰和超额提示；
- `LIVE`、`STALE`、`CLOSED`、`UNAVAILABLE` 状态转换；
- 断线重连、重复事件、乱序事件和异常标的隔离；
- 前端禁止把缺失值替换为硬编码行情；
- AI 输出 Schema、白名单、证据和时间戳校验；
- 仓库敏感路径与凭据模式检查。

### 10.2 Phase 3A 真实验收

在 A 股交易时段使用用户本机终端完成：

1. 6 个核心指数全部取得真实事件；
2. 首页点位、涨跌幅和时间戳与东财终端抽样一致；
3. 运行至少 30 分钟无无界内存增长或重复订阅；
4. 主动断开终端后，UI 在阈值内进入 `STALE`；
5. 恢复终端后自动重连且不产生假行情；
6. 关闭市场后正确显示收盘状态；
7. 仓库和日志中不存在用户凭据。

Phase 3A 只有通过真实交易时段验收才可标记完成。自动化模拟测试不能替代真实行情验收。

## 11. 实施阶段

### Phase 3A：东财国内真实行情

- EastmoneyProvider 与本地行情服务；
- 6 个核心指数；
- 观察池、订阅配额和详情分时；
- 数据状态、缓存、断线重连；
- 删除正式首页硬编码假行情；
- 真实交易时段验收。

### Phase 3B：全球夜盘基础

- AlpacaProvider；
- 美股盘前、盘中和盘后状态；
- 主要市场/行业 ETF；
- 全球夜盘工作区。

### Phase 3C：全球产业主题

- 版本化主题篮子；
- 权重、贡献度与主题排名；
- 自研指标透明解释。

### Phase 3D：AI 跨市场策略

- 海外到 A 股映射；
- 新闻与证据存储；
- DeepSeek 盘前策略草案；
- 历史有效率和 Paper 验证。

## 12. 明确不在当前阶段完成

- 真实账户自动下单；
- 完整全市场涨跌家数和无权限的全 A 扫描；
- 未经验证的收益承诺；
- 使用网页抓取作为实时核心行情；
- 在 Phase 3A 同时完成全部海外主题和 AI 策略。
