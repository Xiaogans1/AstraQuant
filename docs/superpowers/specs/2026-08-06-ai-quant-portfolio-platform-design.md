# AstraQuant AI 量化、模拟账户与策略平台设计

日期：2026-08-06  
状态：已确认总体方向，作为后续实施计划的产品与技术基线

## 1. 决策摘要

AstraQuant 从“真实行情终端 + 分钟规则信号”演进为面向中国 A 股、ETF 与国内期货的本地优先 AI 量化平台。产品必须贯通：

```text
真实行情 → 秒级特征 → 策略/模型 → 组合与风控 → 虚拟委托与成交
→ 持仓/资金/盈亏 → 日月年绩效 → 研究、复盘与模型迭代
```

第一优先级不是继续填充首页占位卡片，而是完成“真实 Tick → 模拟账户 → 虚拟成交 → 实时盈亏”的首个产品闭环。用户可以直接填写初始资金、当前持仓、成本价和可卖数量，从指定时刻开始让策略在真实行情上执行后续虚拟交易。

产品边界不再写死“永不接入实盘”。阶段性边界调整为：

- 当前默认只启用回放、Paper 和持仓镜像模式；
- 未来允许增加只读账户同步与真实委托适配器；
- 实盘必须显式授权，凭据、账户、进程和审计与 Paper 隔离；
- LLM 不拥有委托权限，不能绕过订单管理和确定性风控；
- 任意实盘适配器必须具备总开关、限额、重复单拦截、过期行情拦截和一键熔断。

## 2. 外部调研与采用策略

本项目不整体复制某一个框架，也不把多个框架直接拼成彼此冲突的运行时。AstraQuant 保留自有领域契约、事件流、账户账本、信号和审计核心，通过边界清晰的适配器吸收成熟项目强项。

### 2.1 重点借鉴

| 项目/产品 | 借鉴内容 | 采用方式 |
| --- | --- | --- |
| QuantConnect LEAN | Universe、Alpha、Portfolio Construction、Execution、Risk 的策略分层；回测与流式运行一致 | 架构借鉴，自主实现领域接口 |
| vn.py | 国内期货/CTA/组合语义、本地 Paper、持仓和每日盈亏管理 | 国内规则与模块边界参考；必要时通过隔离适配器复用 MIT 组件 |
| NautilusTrader | 事件驱动、事件溯源、回放、组合、执行和风险分层 | 架构借鉴；不直接引入 LGPL 核心运行时 |
| hftbacktest | Tick/盘口回放、延迟、队列位置和部分成交模型 | 研究与高精度回放的可选适配器，不作为主账户内核 |
| Qlib | 版本化数据、因子、模型、训练、评估和工作流 | 研究层可选 Provider/Runner，产物转换为 AstraQuant `ModelArtifact` |
| RD-Agent(Q) | 因子与模型协同研究、实验自动化 | 后续研究 Agent，不进入实时交易热路径 |
| TradingAgents / FinGPT | 新闻、公告、情绪、正反方研究和金融文本结构化 | 情报流程参考；输出受 Schema 约束的证据和当日计划 |
| TradingView | 图上信号/成交、策略测试器和绩效交互 | 前端交互借鉴，不复制实现或视觉资产 |
| QuantStats | 收益、回撤和风险指标定义 | 可选分析依赖或指标校验参考 |

### 2.2 不采用的方案

1. **整体迁移到 LEAN 或 NautilusTrader。** 功能完整，但会推翻现有 Tauri、React、Python API、东财适配器与领域契约，并增加国内规则适配成本。
2. **让 Qlib、vn.py、hftbacktest 分别维护一套账户与策略状态。** 会形成多套时间、订单、持仓和收益口径，无法提供统一审计。
3. **直接部署海外、加密市场或公开数据集训练的预训练交易模型。** 市场机制、数据频率、盘口层数、费用和标签不同，不能宣称适用于 A 股或国内期货。
4. **LLM 直接逐 Tick 决策或动态改代码。** 延迟、漂移、不可回放和不可重复，无法成为实盘级核心。

## 3. 总体架构：双脑、三环、四模式

### 3.1 双脑

**快脑：秒级实时核心**

```text
东财 Tick/盘口 → 规范化事件 → 增量特征 → 本地已发布模型
→ 策略组合 → 组合构建 → 风控门 → SignalFrame / OrderIntent
```

行情事件到达后立即计算，不采用与行情无关的固定一秒轮询。东财当前免费数据的客观频率为股票约 3 秒、期货约 0.5 秒、指数约 5 秒；界面必须展示真实事件时间、接收时间、数据年龄和源频率，不制造虚假实时性。

**慢脑：研究与情报核心**

```text
公告/新闻/政策/行业/情绪/宏观/隔夜市场
→ 去重、实体映射与来源校验
→ 多角色分析与反证
→ DailyRegimePlan
```

慢脑负责“今天适合使用什么策略、观察什么、回避什么、承担多少风险”，不负责逐 Tick 买卖。

### 3.2 三个闭环

1. **Research 研究环：** 数据快照、标签、因子、训练、防泄漏验证、回测、模型登记和发布。
2. **Live Signal 实时环：** Tick、在线特征、推理、策略组合、风控、信号与告警。
3. **Portfolio 账户环：** 委托、成交、资金、持仓、费用、保证金、盈亏、绩效、恢复和审计。

三个闭环只通过版本化契约通信。研究工具不能直接修改运行账户，实时模型不能直接写成交，UI 不能自行生成信号或盈亏。

### 3.3 四种一致运行模式

| 模式 | 行情 | 初始账户 | 成交 | 用途 |
| --- | --- | --- | --- | --- |
| `REPLAY` | 历史事件流 | 自定义 | 模拟 | 回测、调试、确定性重放 |
| `PAPER` | 真实实时行情 | 自定义资金 | 模拟 | 从零验证策略 |
| `MIRROR` | 真实实时行情 | 手填/导入现有持仓与资金 | 后续交易模拟 | 在真实仓位语境下观察策略 |
| `LIVE` | 真实实时行情 | 券商/期货账户 | 未来真实网关 | 成熟后的显式实盘扩展 |

同一个策略插件和风控接口必须能够运行于四种模式；不同模式使用不同账户 ID、凭据域、事件日志和醒目标识。

## 4. 实时数据与事件内核

### 4.1 事件通道

当前东财桥以请求/响应为主，不能承担持续 Tick 推送。新增独立行情事件通道：

- SDK 进程只负责连接东财终端、订阅和规范化；
- 本地事件总线负责扇出给记录器、特征引擎、图表、策略和账户盯市；
- 控制命令与行情事件分离，避免异步 Tick 污染命令响应；
- 每个事件包含 `event_time`、`available_time`、`received_time`、源序号和去重键；
- 乱序、重复、断线、午休、夜盘跨自然日和重连均有显式状态。

### 4.2 存储和回放

- 原始 Tick/盘口追加写入按交易日分区的 Parquet；
- SQLite 保存订阅、运行、账户、事件索引和恢复检查点；
- DuckDB 用于研究查询和回放切片；
- 回放严格按照当时 `available_time` 推进时间前沿；
- 相同事件、策略、模型和配置必须得到相同信号、委托、成交和账户摘要。

## 5. 策略与模型架构

### 5.1 策略分层

```text
UniverseSelector
→ AlphaModel(s)
→ AlphaEnsemble
→ PortfolioConstructor
→ RiskPolicy
→ ExecutionPolicy
```

- `UniverseSelector`：决定当日候选池、自选、指数/行业关系和流动性门槛；
- `AlphaModel`：规则、树模型、盘口模型或中低频模型输出预期方向、强度、期限和不确定度；
- `AlphaEnsemble`：按市场状态组合多个模型，不允许简单覆盖；
- `PortfolioConstructor`：把信号转为目标仓位，而不是直接买卖数量；
- `RiskPolicy`：应用账户、组合、标的和市场规则；
- `ExecutionPolicy`：在 Paper/Live 模式把目标变化转成委托意图。

### 5.2 首批策略能力

第一条生产研究路线聚焦 A 股/ETF 日内微观结构：

- 五档盘口买卖量不平衡和 OFI；
- 买卖价差、深度、成交方向、成交强度和撤单近似；
- 3/10/30/60 秒收益、波动、价格加速度和成交放量；
- 当前价相对累计均价、VWAP、日内高低点的位置；
- 标的相对指数、行业和相关 ETF 的强弱；
- 涨跌停距离、停牌、流动性和可交易状态。

首个 ML 模型使用 LightGBM 或 XGBoost，原因是推理快、可解释、适合验证特征是否存在样本外信息增益。第二个 challenger 使用针对五档盘口和国内数据重新设计、重新训练的 DeepLOB 风格模型。禁止直接使用海外权重冒充国内有效模型。

后续策略袖套按独立计划增加：

- A 股/ETF 横截面选股与轮动；
- 国内期货 CTA 趋势、突破、均值回归；
- 跨期/跨品种价差和期限结构；
- 事件与公告驱动过滤；
- 多策略组合和风险预算。

### 5.3 模型发布门槛

模型必须先后通过：

1. 防未来数据泄漏与在线/离线特征等价；
2. Purged/Embargo 时间切分和严格样本外测试；
3. 含费用、滑点、涨跌停和成交限制的回放；
4. 多市场状态、参数扰动和异常数据压力测试；
5. Deflated Sharpe、回撤、换手、容量与相对基线评估；
6. `REPLAY → PAPER/MIRROR` 影子运行；
7. 人工批准发布。

未经批准的模型不能产生账户委托意图。

## 6. DeepSeek 与 DailyRegimePlan

DeepSeek/LLM 作为版本化情报传感器参与每日策略，而不是实时执行器。

`DailyRegimePlan` 至少包含：

- 交易日、生成时间、有效期和 LLM/Prompt 版本；
- 市场状态、行业/主题倾向和隔夜风险；
- 推荐观察池、回避池和证据来源；
- 趋势、突破、均值回归等策略的允许状态与权重区间；
- 单标的、行业和组合风险预算上限；
- 公告、政策、财报等事件的禁入窗口；
- 多空证据、冲突分数、置信度和未知项；
- 相对上一版本的修订内容。

实时核心只能消费已验证的结构化字段，并在固定上下限内调整策略权重或风险预算。LLM 不得：

- 修改策略代码、模型权重或风控规则；
- 产生订单或成交；
- 在缺乏证据时自动补全事实；
- 将未经时间对齐的盘后信息用于历史决策；
- 在服务不可用时阻塞本地模型、行情和账户核算。

为了可回测，所有情报事件、结构化结果和计划版本必须保存 `available_time`。没有历史证据快照的 LLM 计划只能参加前向 Paper，不得伪造历史回测。

## 7. 模拟账户、持仓镜像与未来实盘

### 7.1 账户初始化

用户可选择：

- 输入初始现金；
- 手动添加持仓、数量、成本价、可卖数量和建仓日期；
- 后续从 CSV/对账单导入；
- 未来从券商只读接口同步。

手填持仓后，系统创建不可变 `AccountOpeningSnapshot`。策略从用户指定时间开始管理后续虚拟交易；系统不能把导入前的历史盈亏伪装为策略收益。

### 7.2 账本与撮合

账户采用追加式复式语义账本，至少记录：

- 现金冻结/解冻、证券市值、期货保证金和权益；
- 虚拟委托、撤单、部分成交、成交、费用和滑点；
- 持仓批次、可卖数量、平均成本、已实现和未实现盈亏；
- A 股 T+1、买卖单位、价格最小变动、涨跌停和停牌；
- 国内期货合约乘数、保证金、手续费、开平、平今和夜盘交易日；
- 公司行动、ETF/股票除权除息和复权对账户的影响。

默认撮合模型按不同数据能力分级：

1. `QUOTE_TOUCH`：使用最新价/买卖一价和可配置滑点；
2. `DEPTH_AWARE`：使用五档深度估算冲击、部分成交和剩余量；
3. `QUEUE_REPLAY`：研究模式下参考 hftbacktest 的队列与延迟模型。

### 7.3 绩效与归因

界面提供：

- 总资产、现金、持仓市值、保证金、风险度；
- 当日、本周、本月、本年和累计收益；
- 已实现/未实现盈亏、费用和滑点损耗；
- 权益曲线、基准曲线、超额收益和回撤；
- Sharpe、Sortino、Calmar、胜率、盈亏比、Profit Factor 和换手；
- 按账户、策略、模型、标的、行业、信号和市场状态归因；
- 策略建议、虚拟成交和用户真实人工交易记录的分离比较。

### 7.4 实盘扩展边界

未来 `LiveBrokerAdapter` 必须位于独立进程和独立包中。启用前要求：

- 用户显式开启并完成风险确认；
- 单笔、单日、标的、策略和账户限额；
- 交易时段、行情新鲜度、重复单和价格偏离检查；
- 本地硬风控在 LLM、策略和 UI 之外；
- 一键停止新单、撤销活动委托和降级只读；
- Live/Paper 醒目标识和不可混用的账户 ID；
- 完整审计与可恢复订单状态机。

## 8. 前端信息架构调整

当前侧栏 `LATER` 项和首页空白“市场温度 / AI 盘中情报 / 量化候选”只表示旧阶段占位，不能继续作为最终产品结构。

推荐导航：

```text
市场
├─ 市场首页
├─ 行情中心
└─ 智能扫描

交易实验
├─ 模拟账户
├─ 策略实验室
└─ 运行中心

研究
├─ AI 情报
├─ 模型与回测
└─ 复盘分析

系统
├─ 数据与连接
├─ 任务与日志
└─ 设置
```

首页只展示市场概览、当前候选、最新信号、模拟账户摘要、当日计划摘要和运行健康。详细持仓、订单、成交、权益、回撤和归因进入“模拟账户”；模型、参数、回测和发布进入“策略实验室/模型与回测”。

“市场温度”必须来自明确的可计算市场宽度或订阅池统计；数据不足时显示范围和覆盖率。“AI 盘中情报”必须展示真实证据流水线和计划版本。“量化候选”必须来自已发布策略扫描结果。禁止重新填入演示假数据。

## 9. 错误处理与安全降级

- 行情过期、时间倒退或大量丢包：停止新信号和虚拟成交，账户继续按最后已知价标记并显示陈旧状态；
- 特征预热不足：策略保持 `WARMING_UP`，不生成伪信号；
- 模型加载或 Schema 失败：该模型退出组合，不自动切换未批准模型；
- LLM/新闻服务失败：沿用仍有效的计划或退回无情报约束模式，不影响行情、账户和本地模型；
- Paper 撮合失败：停止账户推进并从事件日志恢复，禁止部分写入；
- 账户规则缺失或版本过期：禁止相关品种新增虚拟/真实仓位；
- UI 断开：后台运行和账本继续，重连后从快照与事件恢复；
- 实盘网关异常：默认 fail-closed，不发送替代订单。

## 10. 测试与验收

### 10.1 核心测试

- 事件去重、乱序、时区、午休、夜盘和重连属性测试；
- 离线/在线增量特征等价测试；
- 相同事件流的信号、委托、成交和账户摘要确定性测试；
- 现金、持仓、冻结、费用、保证金和权益不变量测试；
- A 股 T+1、涨跌停、停牌和最小单位测试；
- 期货开平、平今、乘数、保证金和夜盘交易日测试；
- 公司行动和复权对图表、特征与账户口径分离测试；
- 回测防泄漏、Purged/Embargo 切分和多重测试修正；
- Paper 重启恢复、重复事件和断线故障注入；
- LLM Schema、来源、版本、过期和降级测试；
- Paper/Live 隔离、权限和熔断测试。

### 10.2 首个关键节点验收

在一个真实交易时段内：

1. 东财 Tick 进入事件总线并持久化；
2. 用户建立模拟账户并手填至少一个现有持仓；
3. 账户随真实行情更新未实现盈亏；
4. `baseline-v1` 或测试策略产生结构化委托意图；
5. Paper 引擎按国内规则生成虚拟成交和持仓变化；
6. 页面展示总资产、现金、持仓、订单、成交、当日盈亏和权益曲线；
7. 重启后恢复到一致状态；
8. 任一结果可追溯到行情事件、策略版本、风控、委托和成交。

## 11. 分阶段交付顺序

1. **实时事件基础：** 独立 Tick 通道、事件总线、记录和回放。
2. **模拟账户 MVP：** 手填资金/持仓、盯市、虚拟委托、成交和恢复。
3. **国内撮合与绩效：** A 股/期货规则、费用、滑点、权益、回撤和归因。
4. **秒级 ML 基线：** 微观结构特征、LightGBM/XGBoost、模型注册和影子运行。
5. **策略组合与扫描：** Universe、Alpha Ensemble、组合构建和风险预算。
6. **DeepSeek 情报计划：** 证据流水线、DailyRegimePlan、盘中修订和前向评估。
7. **研究自动化：** Qlib/RD-Agent 适配、DeepLOB challenger、多策略实验。
8. **可选实盘：** 独立 Live 网关、硬风控、审批和熔断。

每个阶段都必须在一个可验证逻辑单元完成后提交并推送 GitHub。市场数据、账户数据、日志、模型权重、密钥和运行数据库只保存在本地，不进入 Git。

## 12. 投资路演材料

完成上述核心代码节点后，制作一份简洁、专业、美观的投资路演 PPT。PPT 不堆砌技术名词，重点展示：

- 中国 A 股与国内期货的产品机会；
- 本地隐私、真实行情、秒级快脑和 LLM 慢脑的差异化；
- 从研究、信号、Paper、绩效到未来实盘的闭环；
- 可审计 AI、国内市场规则和事件回放形成的技术护城河；
- 已完成产品截图、真实运行数据、里程碑和未来商业扩展；
- 数据源、模型、实盘权限和监管边界的诚实说明。

演示文稿将在核心功能形成可展示证据后使用专业演示文稿工作流创建并进行逐页视觉检查。
