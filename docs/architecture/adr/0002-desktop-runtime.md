# ADR-0002：桌面本地运行时与进程边界

状态：已接受
日期：2026-07-27

## 决策

AstraQuant Phase 1 使用 Tauri 2 作为 Windows 桌面进程所有者，并由它启动一个
FastAPI 控制服务。控制服务仅绑定 `127.0.0.1:0`，端口由操作系统分配；Tauri 每次
启动生成新的 256 位随机会话令牌，通过环境变量传递，令牌不写磁盘。

控制服务完成 SQLite 迁移和任务恢复后，通过 stdout 发布一行版本化 JSON 握手。
Tauri 校验消息类型、协议版本、loopback host、端口和服务 PID，随后只通过受控命令
向 React 提供 base URL、协议版本与当前会话令牌。

所有 `/v1` 与 `/internal` 请求使用 Bearer 认证。React 通过 HTTP 轮询读取任务与
活动状态，不直接打开 SQLite，也不创建操作系统进程。Worker 由控制服务创建，通过
进程安全队列报告事件，只有控制服务写数据库。

Windows 的 uv 虚拟环境解释器是重定向启动器，会产生不同 PID。开发模式因此从
`pyvenv.cfg` 解析最终基础解释器，并显式设置受控 `PYTHONPATH`，保证 Tauri 持有和
验证的就是实际服务进程。

## 原因

- 数据、日志与任务历史默认留在本机，不依赖服务器账户或云数据库。
- 动态 loopback 端口避免固定端口冲突，短生命周期令牌阻止同机其他页面直接调用。
- Tauri 统一拥有子进程，可以在窗口关闭时先优雅停机，再执行超时终止。
- HTTP 契约把 React、Python 与未来其他桌面/移动端解耦。
- 单写者 SQLite 模型避免 Worker 并发写入造成锁竞争和状态分叉。

## 结果

- `.astraquant/` 是开发运行状态边界，不得提交 Git。
- stdout 在握手完成前后均不得输出非协议内容；诊断日志进入 stderr 与本地 JSONL。
- API 或握手发生不兼容变化时必须升级协议版本，并由桌面端拒绝未知版本。
- Phase 1 不开放局域网访问，不保存交易凭据，也不提供远程控制。
- 打包阶段需要把 Python 控制服务替换为可审计的 sidecar，保持相同握手和关闭契约。
