# 实时模拟账户与交易账本

## 目的与边界

AstraQuant 的首个交易闭环使用用户本机东财终端提供的真实只读行情，但订单、成交、资金和
持仓全部是本地模拟数据。当前代码不持有券商交易凭据，也不存在向真实账户发送委托的路径。

三层能力必须保持隔离：

1. **真实行情层**：读取报价和 K 线，只负责事实输入。
2. **策略与模拟层**：生成版本化建议，通过风控后写入本地虚拟账本。
3. **未来实盘网关**：尚未实现；若未来增加，必须是默认关闭、显式授权、独立风控和可一键熔断的适配层。

## 数据流

```text
东财只读行情
  → 已完成 1 分钟 K 线 / 最新报价
  → RealtimeFeatureSnapshot
  → baseline-v1 SignalFrame + DecisionRecord
  → 建议 / 风控拦截 / 模拟自动执行
  → PaperOrder + PaperFill
  → 现金 + 持仓 + PortfolioSnapshot
  → 桌面账户、盈亏、订单和成交审计
```

`baseline-v1` 是 AstraQuant 自建的确定性动量与成交量规则，用于验证实时决策工程闭环，
不是开源 AI 模型，也不代表已经获得可持续超额收益。后续 AI/ML 模型必须复用相同的
`SignalFrame`、`DecisionRecord`、风控和账本边界，不能直接修改账户状态。

## 账本规则

- Python 金额和价格统一使用 `Decimal`；SQLite 保存规范化十进制字符串，API 以字符串输出。
- 买入优先采用一档卖价，卖出优先采用一档买价；缺失档位时使用真实最新价。没有报价时拒绝成交。
- 默认佣金率为 `0.03%`，最低佣金 5 元；卖出印花税为 `0.05%`；过户费为 `0.001%`。
- ETF 可按证券属性豁免印花税。费用规则通过 `FeeSchedule` 注入，后续可按账户覆盖。
- 买入新增数量当日不可卖；期初录入的可用数量和后续卖出均严格检查可用数量。
- 每笔订单必须携带账户内唯一的 `idempotency_key`。策略自动执行使用稳定
  `decision_id` 派生幂等键，同一决策不会生成第二笔成交。
- 成交、现金、持仓、订单和权益快照在一个 SQLite 事务内写入；失败时整体回滚。
- 账户、持仓、订单、成交和权益快照在应用重启后恢复。删除本机 `.astraquant/` 会清除开发状态。

## 估值与收益

行情观察者只对已缓存且有效的订阅报价触发盯市。盯市会更新持仓最新价、市场价值、未实现
盈亏及账户权益快照，不会改变现金、平均成本或历史成交。当前累计收益以账户权益基线为准；
期初录入持仓时，持仓成本计入基线，避免把导入仓位误算为即时利润。

## 策略安全语义

- 策略执行台默认 `auto_execute=false`，只显示建议、原因、置信度和决策 ID。
- `HOLD`、行情非实时、数据过期和特征预热状态都不会创建订单。
- 显式启用模拟自动执行后，仍需通过单标的仓位上限、现金和 T+1 可用数量检查。
- 任何自动执行都只作用于本地模拟账户；页面持续显示“不发送券商委托”。
