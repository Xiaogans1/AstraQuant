# AstraQuant 工程原则

> 生效：2026-08-08（用户明确指令）。所有开发必须遵守，与速度或便利冲突时，本原则优先。

## 一、最优方案原则（最高优先级）

1. **永远不追求速度。** 没有任何任务可以因为"先跑起来"而选择次优方案。
2. **永远不做临时解决。** 禁止"先用最小实现顶上、以后再改"的渐进式修补；脚手架、占位实现、一次性脚本必须在设计阶段就排除。
3. **要做就做到最优方案。** 每个功能/修复/升级必须先完成最优方案设计（含出处与证据），经用户确认后再完整实现。

## 二、对量化核心的具体化

- **模型以开源成熟实现为基础**：优先复用 Qlib 模型 zoo（LightGBM/DoubleEnsemble/LSTM/Transformer/TRA/HIST 等官方实现）、预训练时序基础模型（Chronos/TimesFM/Moirai，可下载可微调）、FinRL（DRL）等已被社区验证的方案；**不自研低质量算法，不绕开成熟框架另造轮子**。
- **任何方案必须有出处**：论文（DOI 可查）、官方文档、源码、权威实证数据。禁止凭感觉拍脑袋。
- **训练/推理一致性是底线**：point-in-time 特征、防泄漏（purged/embargo）、按交易日 reset、无信息不动作。
- **费用跟随用户配置**：回放/模拟/实盘共用同一 FeeSchedule 语义，绝不写死费率或成本门槛。
- **验证必须全量**：大规模多标的回放报表（空仓/全仓、用户费率/零费用对照）、决策画像存档，而非单标的结论。

## 三、工作方式

1. 先写设计文档（含出处、验收标准）→ 用户确认 → 实施。
2. 实施后全量验证：`uv run pytest -q`、`uv run ruff check .`、`uv run ruff format --check .`、`uv run mypy`（不带参数）。
3. 研究产物（报表、画像、模型工件）存档于 `.astraquant/`（git 忽略），设计文档进 `docs/`。
